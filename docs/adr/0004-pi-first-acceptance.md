# Judge release readiness by Pi functionality

On 2026-11-02 the user prioritized a working standalone Pi extension over copying DSH and discarded the remaining DSH manual comparisons. This supersedes ADR 0001's mandatory behavioral-parity gate: DSH remains design/source context, while the current Pi specification defines supported behavior and acceptance. DSH installation, credentials, host/model runs, side-by-side manual checks and comparative performance are no longer release prerequisites.

Keep the 25 implemented tool capabilities, supported browsers/hosts, preservation and cleanup safeguards, exclusive control and the accepted Windows hook limitation. Reuse existing Pi evidence; preserve historical comparisons as historical evidence, with reference-backed developer utilities optional. Close a Pi deliverable only when its remaining Pi criteria are supported; transfer any shared Pi obligations explicitly before retiring an alignment/diagnosis umbrella. Independent Pi correctness, failure handling and useful responsiveness still matter.
