# Use exclusive control for physical desktop automation

The user chose suppression of ordinary physical keyboard/mouse input while the agent controls the desktop, with a blue border and explicit stop or human handback. This departs from DSH's selectively handled stop keys and Pi's current interference-aborts behavior: accidental interaction should not disrupt an agent task. It supersedes that part of [ADR 0001](0001-preserve-reference-behavior.md), trading simultaneous desktop use for a simpler control contract; the candidate implementation is awaiting full acceptance and all other safeguards remain.

Requirements live in the [spec](../spec.md#exclusive-control); feasibility, responsibility boundaries and acceptance live in the [plan](../implementation-plan.md#exclusive-control-delivery). [BlockInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-blockinput) restricts injection to its owning thread, while [keyboard hooks](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) can suppress events but can be removed on timeout. The candidate uses hooks in the existing independent listener, which allows separately tagged agent input. The native observer ignores physical input only when a downstream hook confirms it consumed the event and the retained listener/protection event remain valid; unconsumed or foreign injected input still invalidates the action. Tagged absolute pointer movement replaces the old expected-SetCursorPos queue.

On 2026-11-01, after the grouped physical check passed and a nonelevated BlockInput probe returned access denied, the user chose hooks with documented Windows limits for the first release. This avoids requiring additional privileges or isolation. Silent hook removal can allow physical events through and make physical stop keys unavailable; neither a live listener nor a stored hook handle proves otherwise. The first release accepts that specific platform limit, without claiming absolute input blocking. Detected protection loss must still stop automation and preserve uncertain-input safeguards. The decision does not waive remaining physical, failure, host or cleanup acceptance, or make #31 complete.
